Data and methods

We first started off by overlaying a map of California with the Dark Target Aerosol Optical Depth layer from the NASA MODIS dataset and the Fires and Thermal Anomalies layer from the same dataset. We added a checkmark filter for the aerosol optical depth layer and the thermal detections layer so the reader can filter by those and choose to only see one or the other. For the thermal detections, we visualize those as circles. We initially scaled the size of the circles by their FRP (which is basically their intensity) but then realized this might confuse the readers into thinking a larger size circle indicates a larger area coverage of that thermal anomaly when that isn't necessarily the case. We solve this by implementing a color scale (noted in the next paragraph). Also, we made it so when you zoom into the map, the points are physically the same size but more spread out because we are zooming in. Also, each thermal anomaly, when hovered over has a tooltip that contains information such as date, time, confidence, FRP, longitude and latitude, and type. Finally, we also added a slider for minimum confidence since each thermal anomaly has a confidence value associated with it (how confident the satellite was in detecting it). This lets users filter by anomalies that have higher or lower confidence. We chose to do this because a user might want to only look at anomalies which we have high confidence were detected if they wanted to draw any concrete conclusions.

For the aerosol optical depth color scale, we decided on the Viridis color scale. We chose this scale because our color for the thermal anomalies were planned to be some sort of orange, red color palette. By choosing this color scale we avoid any color overlap. Furthermore, we originally had continuous binning for the scale of aerosol optical depth, but then we changed this to a discrete binning because it makes it easier for the viewer to pick apart distinct ranges of values. Similarly, for the thermal detection color scale, we used a scale of increasing color intensity of orange. These are also discretely binned.

We added a filter for dates and a calendar selector to make it easier to choose the date you want to arrive at. We initially had a scrollable timeline, but we felt this wasn't good for the reader since if they wanted to find a specific date, they had to very accurately scroll to the date, making it hard to find quickly unlike the calendar selector. Furthermore, our initial scrollable timeline only encompassed one year. If we wanted to include more years, either we would have to have an extremely dense scrollable timeline, which isn't user friendly, or a filter that changed between scrollable timelines. We did not want this, so instead we created the calendar selector and then replaced the scrollable timeline with a scrollable histogram that encompassed the range of years we picked. To solve the issue of having to scroll a lot to get to earlier or later years, we implemented a feature where you could zoom out and view all the histograms in one view. This lets users get a "bird eye view" of all the years, and then also have the option to zoom into the specified year on the timeline they want to view which solves the issue of a scrollable element being too dense in data.

For the map itself, we added a brushing feature where you can select an area on the map. This lets you then get specific information of that selected region such as number of detections, percent AOD coverage, etc. We decided to include this feature because if someone wanted to get information within an area, this would be an easy way to do it.

We also decided to include a filter for the type of thermal anomalies. Each one is classified as a vegetation fire, active volcano, other static land source, offshore, or unknown type. We decided on this because the reader might be interested in viewing the most common types of thermal anomalies and the associated aerosol optical depth. We included tooltips next to certain parts of our visualization such as one for the minimum confidence slider. To a first time viewer or reader, they might not know what those terms mean so having that tooltip clarifies confusion. We also included one next to the aerosol optical depth color scale.

For the development process, we all worked on the same codebase / visualization. As we progressed through adding different design elements or features, we all shared different suggestions for how we could improve the visualization. When we faced an issue, such as how to properly scale thermal anomaly FRP, we spent some time thinking and doing individual research before sharing our ideas. We also kept a notepad of different ideas we brainstormed that would improve the visualization and we then went through them one by one. I would estimate we spent about 3-4 hours working together on the visualization. We also spent some time individually brainstorming before our meetings. I would say the actual implementation of the code for the visualization took the most time. This is because we already had ideas written down prior to implementing the code, but while working on the visualization we encountered issue we had to resolve such as technical or we just wanted to revise some ideas we thought weren't great.

Sources

Thermal detections come from NASA FIRMS annual MODIS records and recent NASA GIBS Terra records. These are downloaded locally and loaded by day. AOD imagery is retrieved live from GIBS and decoded into approximate value ranges. California state and county boundaries come from us-atlas.

AOD coverage begins February 24, 2000; thermal detections begin November 1, 2000. Dates without thermal observations are unavailable, not zero. The selectable range ends at the earlier of yesterday (UTC) and the downloaded snapshot.
